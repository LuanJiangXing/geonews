# GeoNews 视频工作流

把 GeoGuessr 社区的新闻趣闻做成 3–5 分钟视频。**全程只用你提供的素材，
不额外生成任何视频图片**——这是硬约束，成片观感的上限就是你素材的丰富度。

项目位置：本仓库根目录

---

## 目录结构

**一期一个文件夹，月日命名。** 每期的内容和成片都存在自己目录下，互不覆盖。

```
geonews/
├── 0918/                    ← 一期
│   ├── 00-素材.md           你写新闻的地方（只写这一个）
│   ├── 01-归类与叙事.md      阶段一产物
│   ├── 02-待决台账.md        阶段一产物
│   ├── 03-要录什么.md        给你的素材清单
│   ├── 05-片尾链接.md        片尾要展示的链接
│   ├── build.py             这期的拼装脚本
│   ├── assets/video,image/  你录的素材
│   ├── 投递区/              我读不到的内容放这
│   └── out/                 成片
│
├── intro/build.py           片头生成器（共用，不含任何一期内容）
├── outro/build.py           片尾生成器（共用）
├── transition/              转场素材：深/浅两版透明序列
├── logo/                    品牌标识与水印
├── fonts/                   底栏用的像素字体（含选型理由）
├── tools/
│   ├── probe_assets.py      素材体检
│   ├── palette.py           配色唯一来源（每期改 DARK / LIGHT 两行）
│   ├── ticker.py            底栏生成（三层透明图）
│   └── ticker_gif.py        底栏预览动图
└── templates/_project/      空项目模板，新一期从这里复制
```

## 四个阶段

### 1. Brainstorm（问答迭代）

你给新闻（格式随意，不用整理），我**归类 → 按情绪节奏排叙事 → 出「要录什么」清单**。

这一阶段**只到「段落」这一层**：讲什么、大概多长、什么调性、排在哪。
不碰镜头级细节——叙事一改细节全废。

我持续提问，**聊到没有异议才结束**。

### 2. 录制

你按 `03-要录什么.md` 录素材，**解说直接录进视频里**。
录制前后都留一点空白没关系，脚本会自动按语音起止裁掉。

录完丢进 `assets/video/`，跑一次素材体检：

```bash
python3 tools/probe_assets.py 0918
```

它会告诉你每条素材的真实分辨率、时长、有没有声音，并提前警告
"太糊 / 太短 / 没声音"。**这一步能在渲染前拦掉大部分返工。**

### 3. 拼装

从 `templates/_project/` 复制出这期的 `build.py`，按素材填 `SEGMENTS`，然后：

```bash
cd 0918
python3 build.py --full --only pass1   # 裁剪切图 → 放大 → 拼片头正片片尾
python3 build.py --full --only pass2   # 叠水印 → 插转场 → 出成片
```

`SEGMENTS` 每个字段的含义写在 build.py 顶部的注释里。

### 4. 完善

按反馈改 `build.py` 重渲。改一段只重渲一段（pass1 有缓存跳过未变段）。

## 片头与片尾

两者都是**独立生成器，不装任何一期内容**，每期换文案即可。

**动效逻辑保持不变，配色每期轮换、相邻期不重复。** 这样栏目有识别度，
又不会连着几期长得一模一样。

配色集中在 **`tools/palette.py`**，每期只改 `DARK` / `LIGHT` 两行（先看有哪些可选）：

```bash
python3 tools/palette.py list      # 列出 11 套配色，标出本期在用
```

> **换色后必须重新生成两个转场的透明叠加序列**——转场不是动态读颜色的，
> 是预先渲染好的 PNG 序列。不重生成的话，成片还是旧色。
>
> ```bash
> python3 transition/v3/build.py        # 深色转场
> python3 transition/v5-暖米/build.py   # 浅色转场
> ```

```bash
# 片头（7s，信号波动效，深底）
cd intro && python3 build.py --render A --title 第二期 --range 26.09.20-26.09.29

# 片尾（链接字幕，固定 15s，结尾淡出）
cd outro && python3 build.py --links ../0930/05-片尾链接.md --out ../0930/out/片尾.mp4
```

## 底栏（滚动新闻条）

模仿新闻频道的跑马灯，左侧固定品牌词标块，右侧文字从右向左滚。

**条目写在当期 `00-素材.md` 的「滚动底栏新闻条目」那一节**，不另建文件。

```bash
python3 tools/ticker.py 0930/00-素材.md /tmp/layers   # 只出三层，看看参数
python3 tools/ticker_gif.py 0930/00-素材.md -o 0930/out/底栏预览.gif \
    --bg 0930/assets/video/china.mp4 --at 6.0 --duration 134.3  # 出预览动图
```

图层顺序固定：**正片 → 水印 → [底栏底 → 滚动文字 → 词标块] → 转场**。
底栏夹在水印和转场之间，放转场之后的话色带扫过时底栏会浮在色带上，穿帮。

**成片默认是干净的**（用户 2026-09-30 定）：**不叠水印、不烘焙底栏**。
频道标识由底栏左侧那个词标块承担，成片左上角不再单独放角标。

所以每期出**分开的两件**：

```bash
python3 build.py --full --only pass2               # 成片（干净）
python3 build.py --full --bar-only --bar-span 116  # 底栏叠加层（带 alpha，单独出）
```

- **不要主动烘焙带底栏的整片**（`--ticker`），除非明确要求。
- 水印仍可用 `--wm` 显式加，但默认不加。
- `--bar-only` 不加 `--bar-span` 时，出跟成片等长的版本。

细节见 `tools/ticker.py` 顶部注释和 `fonts/README.md`。

## 五个会反复遇到的坑

这些都是踩过的，不是假设。

**① 素材左右带黑边。** 录屏左右各带约 62px 黑边（1280 宽下占 4.84%，上下没有），
放大到 1080p 就是 93px。**水印位置必须用「占输出尺寸的比例」而不是固定像素**
（见 build.py 的 `WM_X_FRAC`），否则会正好压在黑条上。

**② 渲染必须分两段跑。** 一次跑完 1080p 会超过工具调用时限、进程被杀、
产出缺 moov atom 的残缺文件。所以拆成 `--only pass1` / `--only pass2`。

**③ 片头片尾没有音轨。** 直接和有声的正片 concat 会让音频整体错位，
拼装前要补一条等长静音轨（`ensure_audio()` 已处理）。

**④ `ImageDraw` 不做 alpha 混合。** 它把 RGBA 值原样写进像素，
之后 `convert("RGB")` 丢掉 alpha，带透明度的笔触全变满亮度——
表现是"硬跳"而不是淡入。**改片头片尾的绘制时必须画在独立透明层上再合成。**

**⑤ 渲染前要清空帧目录。** 残留的旧帧会被 ffmpeg 一起读进去，
成片时长和内容都会错。

## 品牌资产

`logo/versions/` 是定稿本体（含生成脚本，可一比一复现）。

**大尺寸场景不要直接放大定稿参数。** 定稿的 `condense 0.68`（横向压扁）、
`embolden 4.5`（伪粗体）、`track 0.005`（极紧字距）都是为 80px 小水印优化的，
放到大画面里会显得又粗又挤。大尺寸改用：Light 字重 / condense 0.88 /
embolden 0 / track 0.08，并且**按字高定尺寸**而不是按宽度。

**光栅化 SVG 用 cairosvg，不要用 ImageMagick。** ImageMagick 没有真正的矢量
渲染器，`convert -resize` 会先把 SVG 光栅化成默认尺寸再放大，越放大越糊。
判断有没有糊看**峰值 alpha 是否到 255**。
